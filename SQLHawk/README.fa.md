# 🦅 SQLHawk

**سازنده: rV8Cy** &nbsp;|&nbsp; **نسخه ۰.۱.۰**

📖 English version: [README.md](README.md)

**یک اسکنر شناسایی آسیب‌پذیری SQL Injection، چندزبانه، برای تست امنیتی مجاز و کار باگ‌بانتی.**

SQLHawk سایت هدف را کراول می‌کند، همه‌ی فرم‌ها و پارامترهای URL را پیدا می‌کند، و هرکدام را با سه روش کلاسیک تشخیص SQL Injection تست می‌کند — Error-based، Boolean-based blind، و Time-based blind — و در نهایت یک گزارش HTML تمیز و آماده تولید می‌کند که می‌توانید به صاحب سایت بدهید یا به عنوان اثبات باگ تو یه برنامه‌ی باگ‌بانتی ارسال کنید.

```
Python  -> کراولر، منطق تشخیص، گزارش‌ساز، رابط خط فرمان دوزبانه (فارسی/انگلیسی)
C       -> موتور سریع چندنخی برای چک زنده بودن هاست/پورت قبل از اسکن
Go      -> ابزار اختیاری برای تست موازی و سریع تعداد زیادی لینک همزمان
```

چون تشخیص فقط از طریق HTTP/HTML انجام می‌شود، **مهم نیست بک‌اند سایت هدف با چه زبانی نوشته شده باشد** — PHP، Node.js، Java، Python، Ruby، دات‌نت، Go و غیره؛ همه به یک شکل تست می‌شوند، به شرطی که کوئری آسیب‌پذیر با یک دیتابیس SQL صحبت کند.

## ⚠️ فقط برای استفاده‌ی قانونی و اخلاقی

SQLHawk به‌صورت فعال به هر آدرسی که بدهید درخواست تستی ارسال می‌کند. **فقط این موارد را تست کنید:**

- سیستمی که **خودتان مالک آن هستید**
- هدفی که **قرارداد تست نفوذ کتبی** برایش دارید
- سایتی که **برنامه‌ی رسمی باگ‌بانتی** دارد (مثل [HackerOne](https://hackerone.com) یا [Bugcrowd](https://bugcrowd.com)) و هدف صراحتاً در محدوده‌ی مجاز آن است

اسکن یک سیستم بدون مجوز در اکثر کشورها جرم است. ابزار قبل از هر اسکن واقعی از شما می‌خواهد عبارت `YES` را تایپ کنید. **سازنده هیچ مسئولیتی در قبال سوءاستفاده از این ابزار ندارد.**

برای تمرین، از این محیط‌های تستی عمداً آسیب‌پذیر استفاده کنید:
- [DVWA](https://github.com/digininja/DVWA)
- [bWAPP](http://www.itsecgames.com/)
- [OWASP Juice Shop](https://github.com/juice-shop/juice-shop)
- [Metasploitable](https://sourceforge.net/projects/metasploitable/)

## قابلیت‌ها

- 🌐 **رابط خط فرمان دوزبانه** — اول کار می‌پرسد فارسی یا انگلیسی (`Farsi | English ? (F/E)`)؛ همه‌ی پیام‌ها، سؤالات، و حتی خود گزارش HTML بر اساس همون زبان تولید می‌شن
- 🕷️ **کراولر** — سایت هدف را (فقط همون دامنه، با محدودیت تعداد صفحه) می‌گردد و فرم‌ها و پارامترهای URL را جمع می‌کند
- 💉 **اینجکتور** — هر فیلد را با این روش‌ها تست می‌کند:
  - تشخیص Error-based (تطبیق با پیام‌های خطای MySQL، PostgreSQL، MSSQL، Oracle، SQLite)
  - تشخیص Boolean-based blind (مقایسه‌ی پاسخ شرط TRUE و FALSE)
  - تشخیص Time-based blind (اندازه‌گیری تأخیر پاسخ با payload های `SLEEP`/`WAITFOR`/`pg_sleep`)
- 🧠 **آنالایزر** — از روی پیام خطا حدس می‌زند نوع دیتابیس چیست
- ⚡ **موتور C** — چک سریع و چندنخی TCP برای اطمینان از باز بودن هاست/پورت، قبل از شروع کراول کندتر پایتون
- 🚀 **پرابر Go** (اختیاری) — تأیید سریع و بسیار موازی آسیب‌پذیری Time-based روی لیست بزرگی از لینک‌ها به‌طور همزمان
- 📄 **گزارش‌ساز HTML** — یافته‌ها به ترتیب شدت خطر، با مدرک و راه‌حل پیشنهادی، به فارسی یا انگلیسی، آماده‌ی ارسال به مشتری

## نصب

### 🐧 لینوکس / macOS

```bash
git clone https://github.com/yourusername/sqlhawk.git
cd sqlhawk

# نصب کتابخانه‌های پایتون
pip install -r requirements.txt

# کامپایل موتور C (اختیاری)
cd sqlhawk/engine && gcc -O2 -pthread -o liveness liveness.c && cd ../..

# کامپایل پرابر Go (اختیاری)
cd sqlhawk/engine_go && go build -o bulkprobe bulkprobe.go && cd ../..

# نصب به‌عنوان دستور سیستمی (اختیاری)
pip install -e .
```

### 📱 ترموکس (اندروید)

SQLHawk چون فقط پایتون + چند باینری کوچک C/Go است، رو ترموکس هم بدون مشکل اجرا می‌شود.

```bash
# ۱. آپدیت ترموکس و نصب پیش‌نیازها
pkg update && pkg upgrade -y
pkg install python git clang -y
# (اختیاری، فقط اگه پرابر Go رو هم می‌خوای)
pkg install golang -y

# ۲. دریافت پروژه
git clone https://github.com/yourusername/sqlhawk.git
cd sqlhawk

# ۳. نصب کتابخانه‌های پایتون
pip install -r requirements.txt

# ۴. کامپایل موتور C (کلنگ همون کار gcc رو می‌کنه)
cd sqlhawk/engine
clang -O2 -pthread -o liveness liveness.c
cd ../..

# ۵. اجرا (به‌صورت تعاملی شروع می‌شه — اول زبان، بعد لینک رو می‌پرسه)
python -m sqlhawk.cli

# ۶. باز کردن گزارش HTML (نیاز به اپ Termux:API داره)
pkg install termux-api -y
termux-open sqlhawk_report.html
```

اگه `termux-open` رو نداری، گزارش رو منتقل کن به پوشه‌ی Download گوشیت
(`cp sqlhawk_report.html /sdcard/Download/`، بعد از اجرای یه‌بار `termux-setup-storage`)
و از هر فایل‌منیجر یا مرورگری بازش کن.

**درباره‌ی نمایش متن فارسی رو ترموکس:** ترمینال ترموکس الگوریتم
bidi/شکل‌دهی یونیکد رو پیاده‌سازی نمی‌کنه، برای همین متن فارسی خام
بهم‌ریخته و بدون اتصال حروف نشون داده می‌شه. SQLHawk خودش یه راه‌حل
کوچیک و بدون وابستگی خارجی برای این مشکل داره (نیازی به نصب پکیج
اضافه نیست) که **به‌صورت پیش‌فرض فعاله**. اگه رو ترمینالی اجراش کردی
که خودش فارسی رو درست نشون میده (اکثر ترمینال‌های دسکتاپ)، از
`--no-rtl-fix` استفاده کن تا دوباره برعکس نشه. گزارش HTML اصلاً تحت
تأثیر این موضوع نیست — مرورگرها خودشون فارسی رو درست نمایش می‌دن.

### اجرای غیرتعاملی (برای اسکریپت/خودکار)

برای CI یا اجرای تکراری روی یه هدف از‌قبل‌تأییدشده، `--url`، `--lang` و `-y` رو مستقیم بده تا هیچ سؤالی پرسیده نشه:

```bash
python -m sqlhawk.cli --url https://your-authorized-target.com --output report.html --lang fa -y
```

یا اگه با `pip install -e .` نصبش کردی، از هرجا با اسمش اجراش کن:

```bash
sqlhawk
sqlhawk --url https://your-authorized-target.com --output report.html --lang fa -y
```

### استفاده از پرابر Go (اختیاری، برای لیست بزرگ لینک‌ها)

وقتی یه لیست از نقاط مشکوک به تزریق داری (مثلاً از یه کراول بزرگ‌تر یا لاگ پروکسی)، می‌تونی همه‌شون رو سریع و موازی دوباره تست کنی:

```bash
cat > targets.txt << EOF
https://your-authorized-target.com/search?id=FUZZ
https://your-authorized-target.com/profile?user=FUZZ&tab=1
EOF

./sqlhawk/engine_go/bulkprobe -file targets.txt -delay 5 -concurrency 20
```

### گزینه‌ها

| فلگ | توضیح | پیش‌فرض |
|---|---|---|
| `--url` | آدرس هدف (اختیاری - اگه ندی، تعاملی ازت می‌پرسه) | — |
| `--output` | مسیر ذخیره‌ی گزارش HTML | `sqlhawk_report.html` |
| `--max-pages` | حداکثر تعداد صفحات کراول | `25` |
| `--delay` | ثانیه‌های استفاده‌شده برای تست‌های Time-based | `5` |
| `-y`, `--yes` | رد کردن سؤال تأیید مجوز (برای CI/خودکار روی هدف تأییدشده) | خاموش |
| `--no-banner` | حذف بنر و پاک‌سازی صفحه | خاموش |
| `--no-loop` | بعد از یه اسکن خارج شو، به‌جای پرسیدن لینک بعدی | خاموش |
| `--lang {fa,en}` | زبان رابط — سؤال انتخاب زبان رو حذف می‌کنه | — |
| `--no-rtl-fix` | غیرفعال کردن اصلاح دستی نمایش فارسی (برای ترمینالی که خودش درست نشون میده) | خاموش |

## ساختار پروژه

```
sqlhawk/
├── cli.py                    # نقطه‌ی ورود اصلی (دوزبانه)
├── i18n.py                   # جدول رشته‌های فارسی/انگلیسی
├── rtl.py                    # اصلاح نمایش فارسی برای ترمینال، بدون وابستگی خارجی
├── crawler/
│   └── crawler.py            # پیدا کردن فرم و پارامتر URL
├── injector/
│   ├── payloads.py           # مجموعه payload های تشخیص
│   └── injector.py           # منطق تشخیص error/boolean/time-based
├── analyzer/
│   └── signatures.py         # تشخیص نوع دیتابیس از روی پیام خطا
├── engine/
│   ├── liveness.c            # چک سریع پورت با چندنخی (C)
│   └── liveness_wrapper.py   # پل پایتون به باینری کامپایل‌شده
├── engine_go/
│   └── bulkprobe.go          # پرابر موازی و سریع Time-based (Go)
└── report/
    └── report.py             # گزارش‌ساز HTML (فارسی/انگلیسی)
```

## چطور از این پول دربیاری

۱. تو **HackerOne** یا **Bugcrowd** ثبت‌نام کن و فقط برنامه‌هایی رو تست کن که هدف صراحتاً در محدوده‌ی مجازشونه.
۲. یا مستقیم با کسب‌وکارهای کوچیک صحبت کن، به‌صورت کلی توضیح بده چی پیدا کردی، و قبل از هر اسکن، یه **قرارداد کتبی** (محدوده‌ی مشخص، تاریخ، بند عدم خسارت) بگیر.
۳. از گزارش HTML خروجی SQLHawk به‌عنوان اثبات باگ (proof-of-concept) استفاده کن — همین الان payload، مدرک، و راه‌حل رو داره.
۴. هیچ‌وقت در ازای عدم افشای عمومی یه آسیب‌پذیری پول نخواه — این کار از باگ‌بانتی خارج می‌شه و می‌ره تو باج‌گیری که جرمه. افشای مسئولانه یعنی گزارش باگ بدی، بذاری درستش کنن، و از طریق سیستم رسمی پاداش همون برنامه پول بگیری.
